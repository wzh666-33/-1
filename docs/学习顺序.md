# 学习顺序

找工作和这个项目同时进行。简历先写已经做过的上位机测试。这里每做完一截，再把对应内容补进项目介绍。

## 这 3 天

讲清一条搬运：上层给出起点和终点，RMS 选车并从路线表取出路径，RCS 控制这台车走完并上报。

路径规划在正式产品里是复杂算法。这个项目不写算法。

## 第 2–3 周：一台车的 RCS

仿真一台虚拟车。它不选路，只接受一条路径，例如 P1 → A → B。

先做两个接口：下发路径，查询位置和状态。

用 pytest 覆盖四件事：走完、急停、路径里有不存在的点、离线后状态不再是执行中。

## 第 4 周：MQTT

RMS 下发路径、RCS 上报位置和状态，改成走 MQTT。先在 Windows 上跑通。

## 第 5 周：Ubuntu / Linux

把已经跑通的 RCS 放到 Ubuntu 里再跑一遍。会进入目录、看文件、看进程、看日志即可。

## 第 6–7 周：RMS

地图上放两到三台车，每台车背后都是前面的 RCS。上层只发「从 A 到 B」。

路径不现场计算。事先写好路线表，例如 A 到 B 固定是 P1 → A → B，低电量时固定改去 C。RMS 只做三件事：选一台空闲车、查出对应路线、把路线交给这台车的 RCS。

- 任务、地图、车辆记在 MySQL。
- 哪台车在线、哪个点被占用，记在 Redis。
- 路径仍通过 MQTT 交给 RCS。

测试三件事：任务完成且车回到空闲；两台车不会停在同一个点；一台 RCS 报故障后，任务失败或改派。

电量过低时，RMS 从路线表改取去充电点的路径，由 RCS 开过去。

## 第 8 周：Docker Compose 和 Nginx

每一件都单独跑通过之后，再用 Docker Compose 一次启动 RMS、RCS、MySQL、Redis 和 MQTT。

Nginx 只做转发：外面访问一个地址，请求落到 RMS。

GitHub 上用 Actions 自动跑 pytest。
